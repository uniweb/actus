# 1.0 API-freeze audit — the surface the production consumer doesn't exercise

**Status: resolved.** All four items below are decided and implemented. This is
the deliberate review the [Roadmap to 1.0](../README.md#roadmap-to-10) calls
for, scoped to the feature groups the real consumer doesn't touch.

**Why this doc.** Tagging `1.0` freezes the *whole* public API: after it,
changing a name or shape needs a `2.0`. The core surface is battle-tested —
a substantial production backend (27 controllers, ~13k lines) leans on
controllers, `routes!`/`app_routes!`, `prepare` hooks, `Params`, `WebError`, and
`reply!` continuously. But four feature groups shipped late in 0.4 are used
**zero times** by that consumer, so they had no real-world shake-out. This was
the deliberate once-over of *just those*.

Verdicts: **Freeze** (good as-is), **Decide** (a naming/shape choice made
deliberately), **Clarify** (shape fine, docs pinned a detail).

---

## 1. Per-controller body cap — **Decided: rename to `max_body_bytes`** ✅

Was: attribute `#[controller(max_body = N)]` + `Server::with_max_body_bytes` +
`Controller::actus_max_body()` + `DEFAULT_MAX_BODY_BYTES` — the `_bytes` suffix
was inconsistent across the four.

Decision: standardize on **`max_body_bytes`**. The value is a bare `usize`;
`max_body = 16384` doesn't say bytes-vs-KiB, but `max_body_bytes = 16384` does —
the unit is information, not noise (explicit > magic). Renamed the attribute to
`#[controller(max_body_bytes = N)]` and the trait method to
`actus_max_body_bytes()`; the method and const already matched. Bonus: it now
reads consistently with `with_max_inflight_body_bytes`.

Follow-up decisions (informed by a survey of 2026 practice — Express defaults
JSON to 100 KB, OWASP CRS to ~128 KB, nginx to 1 MB, axum to 2 MB):

- **Unit stays bytes-as-`usize`.** Real limits span 100 KB → 100 MB, so byte
  granularity is required (megabytes can't express the common small caps), and
  it matches axum/actix. Rejected a `1Mb`-style suffix literal (attribute-only,
  non-composable, custom-suffix magic, reopens Mb/MB/MiB ambiguity) and
  `_mb`/`_kb` sibling params (can't span the range; surface sprawl).
- **Added `KIB` / `MIB` / `GIB` consts** (prelude-exported) so `N * UNIT` reads
  the same in an attribute, a builder call, and any expression. Additive.
- **Lowered the default `DEFAULT_MAX_BODY_BYTES` from 16 MiB → 2 MiB**, matching
  axum: a default applies when nobody chose, so it should lean safe. This is a
  behavior change (previously-accepted 2–16 MiB bodies now 413 unless a higher
  cap is set), hence settled pre-1.0; uploads opt into a higher cap explicitly.

## 2. DoS guards — **Frozen as-is** ✅

`Server::with_max_connections`, `with_max_inflight_body_bytes`,
`with_header_read_timeout`, `WebError::Busy(Option<Duration>)` → `503`
(+ `Retry-After`). Consistent `with_*`/`max_*` naming, single well-typed args,
units in the names or the `Duration` type. No change — including keeping the
long-but-precise `with_max_inflight_body_bytes` name.

## 3. Per-controller rate-limit class — **Decided: named struct** ✅

Was: `Router::rate_limit_classes() -> Vec<(String, &'static str)>` — an
unlabeled, asymmetric tuple where nothing at the type level said which element
was the mount and which the class.

Decision: return **`Vec<RateLimitClass>`** where
`RateLimitClass { mount: String, class: &'static str }`. The asymmetry itself is
correct (the mount is computed at router-build time; the class is a `'static`
literal from the attribute) — the fix was making the pair self-documenting at
the call site. Since this function exists *only* for the auditability use case
(the startup coverage check), a named, extensible type fits the framework's
ethos better than a bare tuple. `RateLimitClass` is exported from `actus-server`
and the `actus` facade + prelude. The attribute and `request.rate_limit_class`
were already fine and unchanged.

## 4. Compression tuning — **Decided: rename `quality` → `brotli_quality`** ✅

Corrected from the first draft of this audit, which had two errors: there is
**no public `prefer_brotli()`** (brotli is the default; the only public toggle
is `prefer_gzip()`), and `quality`'s doc was **already** clear about codec and
range. So the real issue wasn't docs — it was the name.

`quality(q: u32)` only ever set the *brotli* quality (the internal field is
literally `brotli_quality`; gzip uses `flate2`'s fixed default). A generic
`quality` over-promised and was a quiet foot-gun (`quality(9)` while preferring
gzip silently did nothing). Renamed to **`brotli_quality(q: u32)`** — named for
the codec it controls (different semantics → different names), which also leaves
clean room for a future `gzip_level()`. Public surface now:
`CompressionLayer::new()`, `.min_size(usize)`, `.prefer_gzip()`,
`.brotli_quality(u32)`.
